# Design - v1.1 lifecycle features

> Status: **draft / proposal**. Scope: `srm uninstall`, progressive (in-place) updates,
> and in-tool self-update. This document records the design, the sequencing, and the
> safety constraints surfaced by a code-grounded review.

## Summary

v1.1 adds three lifecycle capabilities. They are **not equally safe** and ship in order:

1. **v1.1.0 - Foundation + `srm uninstall`** (this slice).
2. **v1.1.x - Progressive updates** (in-place upgrade of binary + config schema + templates + runner agent).
3. **v1.2 - In-tool self-update** (gated on release signing; see [Self-update](#self-update-v12)).

A shared **state manifest** and a dedicated **`internal/lifecycle`** package underpin all three.

## Implementation status (v1.1.0)

Landed on `feat/v1.1.0` (sequential commits, not yet pushed):

- §0 host-bound deregistration - `DestroyRunner` deletes by the agent's local `.runner` id, never by name.
- §1c `srm backup` / `srm restore`.
- §2 `srm uninstall` - scope flags, drain gate, dry-run, plan preview + typed-hostname confirm.
- Robustness - strip the UTF-8 BOM from `.runner` before parsing the agent id; install self-bootstraps the shared `installRoot/.cache` (+ `httpDownload`/`RecordJIT` create their parents) so the uninstall→reinstall round-trip is clean with no workarounds.
- UX - the selected table row highlight spans the full width; the `/` incremental filter now works on **every** list view (Persistent, Ephemeral, Groups, Health), not just Persistent.
- Onboarding - bare `srm` on an unconfigured host runs a **guided first-run wizard** (reusing `srm init`'s form) that writes config and verifies GitHub auth before launching the TUI; `srm init` now also verifies auth after writing. `srm init` is kept for CI / re-init / add-org.

Validated live on the host (2026-06-20, non-destructive): auth/list path (`runners list`, `doctor`), `uninstall --dry-run` plan, `groups list`, and the wizard gating in all three directions - non-root configured host → sudo hint; root + orgs present → straight to TUI (no wizard); root + fresh config → wizard triggers. Filter + interactive form entry are unit-tested (a headless SSH session has no TTY to drive them).

Scoping decisions vs the design below:

- `backup`/`restore` and `uninstall` live in **`internal/service`** (where the orchestrator/client/config plumbing already is), not a separate `internal/lifecycle` package - that refactor is deferred and optional.
- The **`state.json` manifest (§1a) is deferred to the progressive-update phase**: uninstall derives its inventory from live unit enumeration + config (the source of truth), avoiding a manifest that could drift into the authority for destructive ops.
- The first-run **wizard reuses `srm init`** (shared `orgFields`/`orgForm`/`collectOrg`) rather than replacing it - `init` still uniquely serves non-interactive/CI, re-init, and add-another-org, so **no separate `init` command was needed** beyond completing it.
- The **`--replace`-on-create guard** is pending a warn-vs-refuse decision (see [Open questions](#open-questions)).

## 0. Prerequisite fix - host-bound GitHub deregistration

`DestroyRunner` ([internal/service/deploy.go:281-308](../../internal/service/deploy.go#L281-L308))
resolves the GitHub runner to delete by matching `r.Name` across the **whole org** runner
list, then deletes that id. The host-side teardown is correctly local, but the GitHub delete
is name-resolved, not host-bound.

- **Why it (mostly) holds today:** persistent runners register with `config.sh --replace`
  ([internal/runner/orchestrator.go:787](../../internal/runner/orchestrator.go#L787)) and
  GitHub enforces unique runner names per org, so two same-named runners are not normally
  live simultaneously. The dangerous case requires the same name deliberately reused across
  hosts of one org.
- **Why it must be fixed before uninstall:** uninstall deregisters many runners at once;
  re-resolving each by name compounds the hazard and relies on an external invariant rather
  than srm's own record.

**Fix:** persist the GitHub runner **id** locally at create time - the agent already writes it
to the `.runner` file (`agentId`) in the runner tree - and have `DestroyRunner` / uninstall
delete strictly by that id, only for trees this host owns. Treat a name-only match as an error.

**Related footgun:** `config.sh --replace` on *create* lets `srm runners create <name>` silently
take over a same-named runner registered by another host in the org. Add a guard/warning when a
create would replace a registration whose id this host does not own.

## 1. Foundation

### 1a. Host state manifest - `/var/lib/srm/state.json`

Root-only (0600) JSON, written atomically (temp + fsync + rename, the pattern `RecordJIT`
already uses at [orchestrator.go:1017](../../internal/runner/orchestrator.go#L1017)). The
parent `/var/lib/srm` already exists (0700) for ephemeral control files.

Records:

| Field | Use |
|---|---|
| `srmVersion` | self-update downgrade detection; reconcile/doctor "update available" |
| `configSchemaVersion` | migration gate |
| `runners[]` → `{org, name, githubRunnerId, agentVersion, configuredAt}` | **host-bound deregistration** (fixes §0), per-runner agent-version tracking, authoritative uninstall inventory |
| `channel` | stable / latest |
| `installedAt`, `lastUpdate` | audit |

This is the single source of truth that makes uninstall's inventory authoritative
(srm-created vs foreign), enables anti-downgrade, and tracks agent versions. `CreateRunner`,
`EnsureEphemeralSlot`, and `RemoveRunner` update it as they mutate the host.

### 1b. `internal/lifecycle` package

A cohesive home for `Install`, `Update`, `Uninstall`, `Backup`, `Restore`, and the manifest
read/write - mirroring how `internal/service` composes orchestrator + github + config. Today
install logic is scattered across the `Makefile`, `internal/cli/init.go`, and
`orchestrator.EnsureBase`. This package owns the full artifact inventory so uninstall and
self-update don't each re-derive it.

### 1c. `srm backup` / `srm restore`

`srm backup [--out PATH]` → a root-0600 tarball of `/etc/srm` (config + per-org `*.pem` App
keys + `secrets.age`) plus a copy of `state.json`. `srm restore FILE` validates and unpacks it.
`uninstall --purge` and (later) `update` call `backup` automatically before any destructive step.

Rationale: the GitHub App private key is shown **once** by GitHub and cannot be re-downloaded;
`SaveConfig` ([internal/service/manager.go:49](../../internal/service/manager.go#L49)) currently
overwrites config in place with no `.prev` backup.

## 2. `srm uninstall`

Full purge of srm-created host artifacts, with confirmation. Effort: **M** - most destructive
primitives already exist (`teardownService`, `RemoveRunner`, `teardownEphemeral`,
`RemoveEphemeralSlot`, `DestroyEphemeralSlot`).

### CLI

| Command | Behavior |
|---|---|
| `srm uninstall --dry-run` | Print the exact inventory that *would* be removed + a `SKIPPED (foreign)` section + the GitHub deregistration summary. No mutation. |
| `srm uninstall` | Interactive full purge; requires typing the machine hostname to proceed. |
| `srm uninstall --yes` | Non-interactive (automation); still prints the inventory. |
| `srm uninstall --org X` | Scope to one org (see single-user vs isolated rule below). Implies `--keep-config` + `--keep-binary`. |
| `srm uninstall --keep-config` | Preserve `/etc/srm` (config + keys). **Default leaves secrets unless `--purge`.** |
| `srm uninstall --keep-binary` | Preserve `/usr/local/bin/srm`. |
| `srm uninstall --keep-github` | Host-side teardown only; zero GitHub API calls. |
| `srm uninstall --force` | Proceed even when a runner is busy / a lane is mid-cycle. |
| `srm uninstall --purge` | Also remove `/etc/srm` secrets - after an automatic `srm backup`. Loud, double-confirmed. |

### Teardown order

1. Pre-flight: require root; load config; resolve scope.
2. Build inventory from `state.json` (authoritative) + `ListUnits`/`ListEphemeralUnits`
   (enumerable survivors). Mark units with no `state.json` / unconfigured org as **foreign → skipped**.
3. **Busy/drain gate** - refuse (non-zero) if any in-scope runner is busy or a lane is mid-cycle,
   unless `--force`. When GitHub busy-state is unknown (rate-limited / `ClassUnknown`), refuse
   rather than guess. Default to graceful `systemctl stop` + wait for the current job.
4. Confirmation (typed hostname), unless `--yes` / `--dry-run`.
5. **Ephemeral lanes first** - they are `Restart=always`, so `disable --now` before stop, else
   systemd respawns them. Reuse `DestroyEphemeralSlot`.
6. Persistent runners - `RemoveRunner` (host) + delete GitHub **by locally-recorded id** (§0).
   Never delete a runner online on another host.
7. `daemon-reload` + `reset-failed` sweep.
8. Per-org users (isolated mode only): `userdel` the deterministic `srm-<slug>` **only** when the
   name starts with `srm-` and it owns no remaining processes. Never the shared `srm` user under `--org`.
9. Install roots / caches / control dirs by **exact computed path**.
10. `/etc/srm` (only under `--purge`, after `backup`).
11. Binary last (`os.Executable()`; safe to unlink while running on Linux).
12. Emit a report: removed counts + a `SKIPPED` list (foreign units, busy-without-force, cross-host).

### Hard safety rules

- **Touch only what srm can prove it created.** Units are prefix-safe (`actions.runner.`,
  `actions.ephemeral.`); users/caches/dirs are name-pattern-only, so gate them on an
  **ownership marker** (sentinel file / xattr) written at create time, and refuse to delete
  anything lacking it.
- **Never remove shared infra in default mode** - especially `/opt/hostedtoolcache` (a GitHub
  convention, not srm-private) and the shared `srm` user.
- **Single-user vs isolated asymmetry:** in single-user mode `--org X` removes only X's units +
  `{installRoot}/X` + `/var/lib/srm/ephemeral/X`, never the shared user/caches/slice/config/binary.
  In isolated mode `--org X` may fully remove `srm-<slug(X)>` + per-org dirs (they are private to X).
- **Resumable/idempotent** - derive the work list from enumerable units each run so a partial
  uninstall re-runs cleanly.

## 3. Progressive updates (v1.1.x)

Separate **control plane** (srm binary, config schema, systemd templates) from **data plane**
(the actions/runner agent); version each independently. Effort: **L**.

- **Config schema:** add `schemaVersion` to [internal/config/config.go](../../internal/config/config.go)
  + an ordered, idempotent migration chain; back up `config.yaml` → `.prev` before write.
  koanf is lenient (silently drops unknown keys), so **reject `schemaVersion > current` loudly**.
- **Template versioning:** stamp `# srm-dropin-vN` / `# srm-ephemeral-vN` markers into the
  renderers so `reconcile`'s byte-equality flags a bump as drift and `runners refresh` re-applies
  it in place (the existing re-render engine).
- **Data plane:** wire the inert `RunnerVersion` pin
  ([config.go:264](../../internal/config/config.go#L264)) into the download path; add
  `srm runners upgrade` - staged, canary (`--org`), **idle-only**, resumable via `state.json`.
- **Mixed-version hazard:** in a shared org, a new-template host and an old-binary host fight over
  the same drop-ins (each sees the other as drift). Mitigate with the version marker
  ("newer marker = authoritative-skip") + always update the binary before `reconcile --fix`.
- Add `-buildvcs=false` to the build targets so dirty/tarball rebuilds don't break.

## 4. Self-update (v1.2)

`srm update` / `srm self-update`: resolve the latest `erlete/srm` `v*` via the Releases API
(`go-github` is already a dep), semver-compare to `main.version`, download `srm-<ver>-ubuntu-x64`,
**verify**, atomically replace the binary (temp-in-dir + fsync + rename, keep `srm.prev`),
re-exec `--version`. Effort: **M** + a one-time `release.yml` signing change.

### Trust model - the centerpiece (do NOT ship checksum-only)

The `.sha256` is **same-origin and same-write-scope** as the binary (`release.yml` has
`contents: write`), so a SHA match proves *transport integrity*, not authenticity. A compromised
release or leaked Actions token swaps both - and the root binary is baked into every ephemeral
slot unit (`ExecStart=/usr/local/bin/srm`,
[orchestrator.go:41](../../internal/runner/orchestrator.go#L41)), so a trojaned update runs as
root across every org on the next cycle.

**Required before shipping:**

- **Detached signing** - minisign (Ed25519; ~50 LOC verify on stdlib `crypto/ed25519`, fits the
  "pure Go, CGO off" posture) signed in `release.yml` with a key held **outside** repo write-scope
  (Actions secret or OIDC-keyless cosign as the heavier alternative). Embed the **pinned public
  key** in the binary; verify the signature *before* the swap. SHA stays as a corruption pre-check.
- **Anti-downgrade** - refuse `<= current` unless `--force`; put the version inside the signed payload.
- **Hygiene** - explicit command only (never automatic, never from a slot unit); platform-guard to
  `linux/amd64`; pre-swap self-test; detect a dpkg-managed install and defer; `doctor`'s
  "update available" notice is best-effort, cached (TTL + jitter), never fails a core command.

### Alternative - signed `.deb` / apt repo

dpkg gives update + uninstall + integrity + dependency tracking + `unattended-upgrades` for free on
Ubuntu (the only target). Cost: repo infra + GPG key custody, and no help for `scp`-the-binary users.
Recommendation: ship the self-updating binary now; add a signed apt channel later. Self-update should
detect a dpkg-managed install and defer to apt.

## Sequencing

1. **v1.1.0:** §0 host-bound deregistration → §1 state manifest + lifecycle pkg + backup/restore →
   §2 uninstall.
2. **v1.1.x:** §3 schemaVersion + migrations + versioned templates + `runners upgrade`.
3. **v1.2:** §4 self-update, gated on release signing.

## Open questions

- Manifest schema versioning - version `state.json` itself for forward-compat.
- `--replace`-on-create guard: warn-only, or refuse when the id isn't host-owned?
- Update channels (`stable`/`latest`) - land with progressive updates or self-update?
- Audit log: journald (`journalctl -t srm`) vs the existing file logger.
